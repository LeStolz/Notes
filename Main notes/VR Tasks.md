# Application Control
> 3D control differs from 2D, requiring users to handle more DOF, use varied input/output devices, and face added challenges in [[Human-Computer Interaction]] design due to the extra dimension.

Indirect interaction techniques:
- Execute an app.
- Change system state.
- Change interaction mode.
- Command line, UI.
## Menus
### 3D hand-oriented menus
**1-DOF Menus:** Rotate hand to rotate a circular menu around one axis to select an item; effectiveness depends on hand/wrist motion and rotation axis.
**Widget-based menus:** The menu stays fixed, and the user selects items by manipulating a virtual object attached to their hand.
### 3D Widgets 
Graphical interface elements in virtual environments used to control system functions or selected objects; placement is crucial, usually near the objects for context-sensitive interaction. Metaphor for slides, knobs, switches,...
### 2D menus
## Voice control
Used to initialize, select, or command, and to enable/disable voice input; especially useful when the hands are busy.

Not suitable everywhere, limited vocabulary, requires learning commands, hard to remember them all, and often lacks a visual display of available commands.
## Gestures
Uses the hand directly for initialization, selection, or commands; effective but calibration may be imprecise (e.g., sign language).

Users must know all gestures, complex applications require many gestures and gestures can’t directly replace graphical menus; feedback (e.g., visual cues) helps improve usability.
## Tools 
### Physical tools
Real-world supports mirrored in VR, used for one or more functions, with integrated control, tactile feedback, shape and labeling indicating use, and menus directly linked to the input device.
### Virtual tools (toolbox)
Use proprioceptive cues to position the control system (e.g., on a belt), enabling quick access; selection is faster in stereo vision, arranged as menus or a real-world-style toolbox, though using it can distract from the main task.
